# Bakunzi Bake Fiston — Portfolio & CV

A Laravel + MySQL portfolio and résumé website with a small, authenticated admin area for editing every piece of content.

**Stack:** Laravel 13 · PHP 8.3+ · MySQL 8 / MariaDB 10.4+ · Blade · Tailwind CSS 4 · Vite · Lucide icons · DomPDF

## Features

- **Public site:** home page (hero, about, featured projects, skills, experience, education, CV call-to-action, contact), project gallery with category filters (`/projects`), project case-study pages (`/projects/{slug}`), online CV (`/resume`), PDF CV download (`/resume/download`), `sitemap.xml`.
- **Dark theme by default** with an optional, remembered light mode. The layouts are responsive, the mobile menu is keyboard-accessible (Esc closes it), and the in-page navigation highlights the current section.
- **PDF CV:** generated by DomPDF from the database as real, selectable, single-column text. If you upload your own PDF under *Settings → Resume*, that file is served instead. The `/resume` page also has a print stylesheet, so *Print → Save as PDF* works as a fallback.
- **Contact form:** server-side validation, CSRF protection, a honeypot field, a minimum fill time, and rate limiting (3/min and 10/hour per IP). Every message is stored in `contact_messages` and appears in the admin inbox. It is also emailed when a recipient and a mailer are configured. If email delivery fails, the message is still saved and the visitor sees an accurate confirmation.
- **Admin area (`/admin`):** projects (with images, screenshots, draft/published, featured, ordering), project categories, skills, experience, education, certifications, social links, profile/site settings, and contact messages.

### Content safeguards

- **Draft projects** return 404 and are excluded from listings, the CV and the sitemap.
- **Education** is shown as "Bachelor's-level studies in …" or "Master's-level studies". A formal qualification title appears only when the status is *Qualification awarded*, which the admin form allows only after an explicit confirmation checkbox.
- **Experience** entries appear only when published *and* given a position or organisation. Until real roles are added, the Experience section lists the projects contributed to, without assigning any position.
- **Empty values are omitted.** Empty URLs, technologies, roles and similar fields are never rendered, so there are no broken links.
- **Projects without a thumbnail** use a neutral generated cover (initials on a grid), not a fake screenshot.

## Database

| Table | Purpose |
|---|---|
| `site_settings` | Key/value profile settings (defaults live in `config/portfolio.php`) |
| `social_links` | LinkedIn, GitHub, etc.; hidden until a URL is set |
| `project_categories` | Filter categories |
| `projects` | Portfolio entries (`project_category_id` FK, nullOnDelete; JSON `technologies`, `key_features`, `screenshots`) |
| `skill_categories`, `skills` | Grouped skills (`skill_category_id` FK, cascade) |
| `experiences` | Work experience (`type=employment`) and project contributions (`type=project`, optional `project_id` FK) |
| `education` | Studies with `status`: `pursued`, `in_progress` or `awarded` |
| `certifications` | Optional; the section appears only when entries exist |
| `contact_messages` | Stored contact submissions |
| `users` | Admin accounts (`is_admin`, not mass assignable) |

The seeders are **idempotent** (`firstOrCreate`). Running `php artisan db:seed` again never overwrites content you have edited.

## Local setup

```bash
composer install
npm install
cp .env.example .env && php artisan key:generate
# create a MySQL database (utf8mb4) and set DB_* in .env
php artisan migrate --seed
php artisan storage:link
php artisan portfolio:admin you@example.com   # prompts for a password (min. 12 chars)
npm run build                                 # or `npm run dev` while developing
php artisan serve
```

Tests use a separate MySQL database, `portfolio_test` (see `phpunit.xml`). Create it first, then run `php artisan test`.

## Environment variables

| Variable | Notes |
|---|---|
| `APP_NAME`, `APP_URL` | Use the public HTTPS URL in production; an `https://` `APP_URL` forces HTTPS links |
| `APP_ENV=production`, `APP_DEBUG=false` | **Required** in production so errors and credentials are never exposed |
| `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` | MySQL connection |
| `MAIL_MAILER`, `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_SCHEME`, `MAIL_FROM_ADDRESS`, `MAIL_FROM_NAME` | SMTP for contact notifications. With `MAIL_MAILER=log`, messages are only stored |
| `CONTACT_RECIPIENT` | Inbox for contact notifications; falls back to the public contact email set in *Settings* |
| `SESSION_DRIVER`, `CACHE_STORE` | `database` by default (works on shared hosting) |

## Deploying to cPanel / shared hosting

1. On your machine, run `composer install --no-dev --optimize-autoloader` and `npm ci && npm run build`. `public/build` must be uploaded, because shared hosts usually have no Node.
2. Upload the project **outside** `public_html`, then point the domain's document root to the project's `public/` folder. If the document root cannot be changed, copy `public/` into `public_html` and update the two paths in `index.php`.
3. Create the MySQL database and user in cPanel, then fill `.env` (with `APP_ENV=production` and `APP_DEBUG=false`).
4. Over SSH or the cPanel Terminal, run:
   ```bash
   php artisan key:generate   # only if APP_KEY is empty
   php artisan migrate --force
   php artisan db:seed --force
   php artisan storage:link
   php artisan portfolio:admin you@example.com
   php artisan config:cache && php artisan route:cache && php artisan view:cache
   ```
5. Make sure `storage/` and `bootstrap/cache/` are writable by PHP. Required PHP extensions: `pdo_mysql`, `mbstring`, `dom`, `gd`, `fileinfo`.

No queue worker or cron job is required. Contact emails are sent synchronously.
